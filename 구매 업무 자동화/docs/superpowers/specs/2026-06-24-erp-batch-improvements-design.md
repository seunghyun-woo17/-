# 부산사무소 ERP — 기능 개선 배치 설계서

- 작성일: 2026-06-24
- 대상: `구매 업무 자동화/Phase1_파일분리/` (프론트엔드 프로토타입, localStorage 기반)
- 담당: 우승현 (SCM)
- 성격: 여러 탭에 걸친 UI/UX·기능 개선 배치(23개 항목)

---

## 1. 배경 / 목표

사전 테스트 중 발견된 개선점과 신규 요구사항을 영역별(설계 / CX·OP / SCM / 재고 / 출고 / QC FAT / 문서산출물)로 일괄 반영한다.
대부분은 명확한 UI/UX 수정이며, 4개 항목만 설계 결정이 필요해 사전 확정했다.

## 2. 확정된 설계 결정

| 항목 | 결정 |
|------|------|
| 권한 제한(설계 관리자만 / QC팀만) | **백엔드 로그인 단계로 연기.** 지금은 UI 변경 없이 CLAUDE.md·요구사항 문서에 "계정별 역할 권한" 요구사항으로 명문화 |
| 불량(DEFECT) 이력 처리결과 | **4종 모두 관리**: 협력업체 반품/교체, 수리 후 재입고, 폐기(Scrap), 보류/자체보관 |
| 선급 코멘트 양식 | **SharePoint 엑셀 연동 방식**: 코멘트 추가 → SharePoint 엑셀 링크 열기 → 작성 → 업로드 → 해당 호선·컬럼 파싱 → 완료율 자동 갱신. 선급별 실제 양식은 추후 폴더 제공 시 파싱 매핑만 조정 |
| 출고율 100% 기준 | **품목별 필요수량 각각 100%** (호선 BOM 전 품목이 각자 100% 출고되면 완료) |

## 3. 영역별 상세 설계

### A. 설계 탭 (`js/phase0.js`)

**A1. 호선 등록 폼에 Yard 입력칸 추가**
- 현재: 호선 등록 폼에 Yard 입력 없음 (`vessel_master.yard`는 CX/OP에서만 입력)
- 변경: 등록 폼에 Yard 입력칸 추가 → 단일 `vessel_master.yard`에 저장 → CX/OP·FAT·360뷰에 자동 반영
- 수용 기준: 호선 등록 시 Yard 입력 → CX/OP 현황·FAT 검사정보의 YARD에 동일 값 노출

**A2. 정보수정 / BOM / 삭제 권한 제한 → 연기 + 문서화**
- 현재: `editVessel`/`openVesselBOMEditor`/삭제 버튼이 모두에게 노출
- 변경: **지금 코드 변경 없음.** 다음 문서에 요구사항 추가
  - `구매 업무 자동화/CLAUDE.md` — "권한 모델" 절 신설
  - `docs/요구사항_명세서.md` 및/또는 `docs/기능_요구사항_정의서.html` — 역할 권한 요구사항(ID 부여)
- 요구사항 내용: "로그인 후 계정별 역할(설계/SCM/QC/관리자)에 따라 기능 노출·수정 권한 차등. 설계 탭의 호선 정보수정·BOM·삭제는 설계 관리자만, 선급별 참고문서 수정은 QC팀만."

### B. CX/OP 탭 (`js/phase-cxop.js`)

**B1. 호선명 밑줄 제거**
- 현재: 호선명에 의미 없는 밑줄(`text-decoration:underline` 등) 존재
- 변경: 밑줄 스타일 제거 (클릭 동작이 있으면 유지하되 밑줄만 제거)

**B2. D/L 칸의 "계약일" 문구 삭제**
- 현재: D·L(`dl_date`) 라벨/플레이스홀더/툴팁에 "계약일" 표현이 있어 설계 탭 `contract_date`와 혼동
- 변경: D·L 관련 UI에서 "계약일" 문구 제거 (D·L은 설계 계약일과 별개임을 명확히)

### C. SCM 입고검수 (`js/phase23.js`)

**C1. 품목 선택 드롭박스 — 품목명 위주 표시**
- 현재: 드롭박스 option이 `item_code` 위주(`item_code — description 30자`)
- 변경: 품목명을 앞세워 표시 (예: `품목명 (item_code)`), 선택 시 코드/명 동기화

**C2. 품목코드 ↔ 품목명 자동 매칭**
- 변경: 드롭박스/입력에서 한쪽(코드 또는 명)을 선택·입력하면 다른쪽 자동 채움. 매칭 소스는 현재 PO의 `po_line`(item_code, description)

**C3. 입력칸 순서 재배치**
- 변경: 입력 순서를 **품목명(드롭박스) → 품목코드(자동 표시) → S/N 입력** 으로 재배치 (현재 DOM 순서 확인 후 자연스러운 흐름으로)

**C4. QR 라벨 표기: S/N + 품목명**
- 현재: 생성된 QR 옆 표기가 `S/N + 품목코드`
- 변경: 사람이 읽는 라벨 텍스트를 `S/N + 품목명`으로 변경. **인코딩되는 QR 페이로드의 item_code는 유지**(재스캔 매칭에 필요), 품목명은 `po_line.description`에서 조회해 라벨에만 표기. 단건(`printSingleQR`)·일괄 인쇄 모두 적용

**C5. 스캔 목록 표 정리 (품목명·품목코드·S/N·스캔날짜)**
- 현재: 스캔된 제품 목록 표기가 코드 위주, 테스트 시 `MOCK-2026-0001` 같은 S/N 등장
- 설명: `MOCK-YYYY-NNNN`은 실제 스캐너 없이 테스트하려고 `dev-mock.js`가 생성하는 **가짜 S/N**(개발 전용, 서버 전환 시 삭제 대상). 로직 자체는 정상이며 제거할 데이터가 아님
- 변경: 스캔된 제품 목록 표를 **품목명 / 품목코드 / S/N / 스캔날짜** 4컬럼으로 명확히 표시

**C6. 입고완료 안내문구 교체**
- 현재: 입고검수 완료 시 안내창에 "PHASE 4 ~" 문구 노출
- 변경: 사용자 친화 문구로 교체 (예: "입고 검수가 완료되었습니다. 서류 첨부 화면으로 이동합니다.")

### D. 출고처리 (`js/phase5.js`)

**D1. 재고 목록 — 제목 및 그룹핑**
- 현재: 출고처리 탭의 재고 목록 제목이 "선택", 행이 S/N 평면 나열
- 변경: 제목 **"재고 목록"**, 행을 **품목명별 그룹**으로 묶고 품목명 클릭 시 드릴다운(세부 S/N 표시). 재고 탭의 2단계 뷰 패턴 재사용

**D2. BOM 출고율 + Packing List 게이팅**
- 현재: 출고처리 버튼 → 즉시 Packing List 노출
- 변경:
  - 출고 처리는 호선 단위로 S/N을 SHIPPED 처리 (출고 대상 호선 컨텍스트 필요 — `outgoing_log`에 vessel 기록)
  - **호선별 출고 현황**에 **BOM 대비 출고율 %** 표시: 각 BOM 라인(`vessel_bom`: vessel_code·item_code·필요수량) 대비 해당 호선으로 SHIPPED 처리된 수량 비율을 품목별로 계산
  - **모든 BOM 품목이 각자 100%일 때만 Packing List 버튼 활성화** (미달이면 비활성 + 부족 품목 표시)
  - 활성화된 버튼 클릭 → 해당 호선 Packing List 문서 자동 생성·출력
- 수용 기준: BOM 일부 미충족 시 버튼 비활성 + 진행률(%) 노출, 전 품목 100% 시 활성화·문서 생성

### E. 재고 현황 (`js/phase5.js`)

**E1. 헤더 통계 변경**
- 현재: 재고 보유 품목 종류 / 부족 품목 / 현재 재고 수량 / 검사요청
- 변경: **재고 보유 품목 종류 / 검사요청 / 검사완료** (부족품목·현재재고수량 제거, 검사완료 추가)
  - 검사요청 = `inventory.status === 'INSPECTION_REQUESTED'` 또는 `outgoing_log` 미완료 검사요청 건
  - 검사완료 = 검사요청 중 `completed === true` 건 (`phase-inspection.js`의 결과 저장 기준)

**E2. 불량(DEFECT) 이력관리**
- 현재: 검사 불량 시 `inventory.status='DEFECT'`로만 표시, 후속 처리 이력 없음
- 변경: 불량 제품 처리 액션 + 이력 추가
  - 신규 테이블 `defect_log`: `{ defect_id, serial_no, item_code, action, supplier_code, action_date, result_date, memo, created_at }`
    - `action`: `RETURN`(협력업체 반품/교체) · `REPAIR`(수리 의뢰) · `SCRAP`(폐기) · `HOLD`(보류/자체보관)
  - 불량 목록 화면에서 행 선택 → 처리 모달(액션·업체·날짜·메모) → `defect_log` 기록 + `inventory.status` 전이
    - `REPAIR` 완료 처리 / `RETURN` 교체 입고 → `IN_STOCK` 복귀 (`result_date` 기록)
    - `SCRAP` → `inventory.status='SCRAPPED'`(가용·전체 집계에서 영구 제외)
    - `HOLD` → `DEFECT` 유지(보류 표시)
  - 불량 이력 조회: 해당 S/N의 `defect_log` 타임라인 표시

**E3. 대여 반납 → 재고 복귀**
- 현재: `status='RENTED'`만 존재, 반납 처리 없음
- 변경: 대여중 제품에 **반납 버튼** → `inventory.status` `RENTED → IN_STOCK` + `outgoing_log`에 `action='RETURNED'` 이력(반납일·메모) 기록

### F. QC FAT 관리 (`js/phase-fat.js`)

**F1. 검사정보 수정 잠금 / S/N 삭제**
- 변경: 호선/검사 정보 중 **FLAG·YARD·Product는 readonly**(설계 정보 자동 반영, 직접 수정 불가). **S/N 입력 항목 삭제**

**F2. 선급 코멘트 SharePoint 엑셀 연동**
- 현재: in-app 개별 코멘트 입력 폼(`fat_comment` 수기 입력)
- 변경 (경량, 기존 구조 재사용):
  1. "코멘트 추가/관리" 버튼 → **SharePoint 엑셀 링크 열기** (URL은 설정값 — 미정이므로 격리된 config 상수로, 선급별 다른 링크 가능)
  2. 사용자가 SharePoint/오프라인에서 작성
  3. 앱에서 **작성 엑셀 업로드** → 파싱
  4. 파싱 결과로 해당 `fat_id`의 `fat_comment` 행 갱신 (code·content·done_date 등) → 기존 **완료율 자동 산출** 로직 재사용
  - 파싱 매핑(`_FAT_COMMENT_HMAP` 류)은 **단일 위치에 격리**하여, 추후 실제 선급 양식이 폴더로 제공되면 매핑만 수정
  - 현재 양식 미확정: 기본 매핑(완료일/상태·코드·내용·호선 컬럼)을 두고 동작시키되, 실제 양식 도착 시 확정
- 기존 SheetJS(xlsx) + CX/OP 업로드 패턴(`onCxopExcelUpload`/`applyCxopExcel`) 재사용

**F3. 완료일 → COMPLETE 배지 + 완료율 연동**
- 변경: 코멘트에 `done_date`가 있으면 **COMPLETE 배지** 표시, 완료율은 done_date 보유 행 비율로 자동(기존 로직). 업로드 파싱으로 done_date가 채워지면 즉시 반영

**F4. 상태 변경이력에 코멘트 완료 이력**
- 변경: 코멘트 업로드/완료 처리 시 `fat_history`에 자동 로그 기록 (예: "선급 코멘트 처리 — 완료 N건 / 완료율 X%")

**F5. 선급별 참고문서 수정 권한 → QC팀만**
- 변경: A2와 동일하게 **권한 시스템 연기 + 문서화** (지금 UI 변경 없음). 요구사항 문서에 "선급별 참고문서 수정은 QC팀만" 명시

**F6. MED 인증서 행추가 팝업 확장**
- 현재: 행 추가 팝업이 좁아 가로 스크롤 발생
- 변경: 모달 폭 확장 / 반응형 그리드 레이아웃으로 **가로 스크롤 없이 전체 입력칸 노출**

### G. 문서산출물 (`js/phase4.js`)

**G1. FAT 문서 추가 팝업에 문서제목 드롭박스**
- 변경: FAT 문서 추가 팝업의 문서제목 입력을 **드롭박스**로 (자주 쓰는 FAT 문서 제목 목록 제공 + 직접 입력 옵션 가능)

**G2. 전반 시스템 점검**
- 사전 테스트에서 다수 오류 발견 → 시스템 점검
- 변경: 본 배치 구현 후 **검증 스윕** 수행
  - `node --check` 전 JS 파일 문법 검사
  - 깨진 onclick/id 참조, 미정의 함수 호출 grep 점검
  - 문서산출물(phase4) 탭 동작 점검 + 발견 버그 수정
  - 사용자 수동 UI 확인 가이드 제공

## 6. 미해결 / 추후 과제

- **SharePoint 엑셀 URL**: 미정 → config 상수 placeholder로 두고 추후 입력
