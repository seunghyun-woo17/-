# 부산사무소 ERP — 중분류 기반 재고·납품계획 설계서

- 작성일: 2026-06-30
- 대상: `구매 업무 자동화/Phase1_파일분리/` (프론트엔드 프로토타입, localStorage 기반)
- 담당: 우승현 (SCM)
- 성격: BOM 계층 분류(대/중/하) 도입 → 재고현황 중분류 그룹화 + SCM 중분류별 납품일정·소요계획

---

## 1. 배경 / 목표

현재 품목코드(`item_code`)는 엑셀의 자재관리코드(예: `SC0002`)를 그대로 써서, **코드만 봐선 어떤 제품·계열인지 알기 어렵다.** 제품은 BOM 기준으로 **대분류 → 중분류 → 하분류** 트리로 구성된다(아래 이미지 기준).

목표:
1. 품목을 **중분류**로 묶어 보이게 해서 코드↔제품 연관성을 직관화한다.
2. 같은 호선이라도 **중분류별 납품일자**가 다르므로 이를 입력·관리한다.
3. 중분류별 납품일정 대비 재고를 비교해 **추가 발주와 최소 3~6개월 계획**을 세울 수 있게 한다.

> 분류 체계(어떤 품목이 어느 중분류인지)는 관련팀 논의로 정립 중이며, **BOM 엑셀을 재작성**해 시스템에 반영한다. 본 설계는 분류 *값*이 아니라 분류를 담는 *구조*를 정의하므로, 최종 분류가 무엇이든 그대로 수용한다.

## 2. 계층 모델 (확정)

| 레벨 | 명칭 | 의미 | 예시 | 호선당 개수 |
|------|------|------|------|-------------|
| LV1 | **대분류** | 제품 전체 (= 기존 모델/완제품) | HiNAS Control & HiDOM | 1 |
| LV2 | **중분류** | 조립체·구역 — **그룹·납품·계획의 기준 단위** | Main Rack, Client Server, Camera Housing, Display Unit | 여러 개 |
| LV3 | **하분류** | 개별 품목 (= `item_code` / `item_name`) | Main SERVER, FIREWALL, IR CAMERA | 여러 개 |

- **대분류는 새 데이터로 거의 불필요** — 사실상 기존 `vessel_bom.model`과 동일.
- **중분류가 핵심 단위**: 재고현황 그룹핑, 납품일정, 소요계획이 모두 중분류 기준.
- **코드 체계는 불변**: `item_code`(자재관리코드)는 그대로. 분류는 데이터로 부착(아래 3장).

## 3. 확정된 설계 결정

| 항목 | 결정 |
|------|------|
| 코드 반영 방식 | **코드 체계 불변.** 대/중/하분류를 별도 데이터로 부착하고, 화면에서 중분류로 그룹 표시 |
| 분류 출처 | **재작성할 BOM 엑셀.** 파서가 중분류 컬럼을 읽어 저장 |
| 분류 전파 방식 | **lookup 단일 소스(접근 A).** `getItemCategory(item_code)` 헬퍼로 표시 시점 조회 → 기존 `inventory`/`po_line`/`outgoing_log` 백필 0 |
| 재고현황 구조 | **중분류(최상위) → 하분류 품목 S/N** 2단계. **제품(모델)로 구분하지 않음** (재고는 호선·제품 공용 풀이라 모델로 쪼개면 왜곡) |
| 납품일정 입력 | **SCM 신규 "납품일정" 탭** — 호선별 중분류 납품예정일·실제납품일을 **직접 입력 + 엑셀 파싱** |
| 계획 화면 위치 | **중분류 클릭 상세에 동반** — 그 중분류의 품목 S/N 재고 + 3개월 납품계획·추가발주를 함께. SCM 납품일정 탭은 6개월 전체 시야 |
| 계획 수요 집계 | **전 호선 합산(모델 전체 합산).** 그 중분류를 필요로 하는 모든 호선의 납품일정·필요수량을 합산(재고가 공용 풀이므로 전사 발주 계획에 적합) |
| 리드타임 자동경고 | **2차(YAGNI).** 1차는 충족/부족만, 추후 리드타임 도입 시 "이미 늦음" 자동판정 추가 |

## 4. 데이터 모델

### 4.1 신규/변경 필드

- `bom_catalog[0].groups[].items[]` 에 **`mid_cat`(중분류)** 추가 (필요 시 `mid_seq` 표시순서, `location`)
- `vessel_bom` 레코드에 **`mid_cat`** 추가 (이미 `gubun`/`model` 보유 → 필드 1개 추가)
- 신규 테이블 **`delivery_schedule`** (db.js `DB`에 추가):

```
delivery_schedule: {
  ds_id        : uid('DS'),
  vessel_id    : vessel_master FK,
  mid_cat      : 중분류명,
  planned_date : 납품예정일 (YYYY-MM-DD),
  actual_date  : 실제납품일 (없으면 ''),
  memo         : 비고,
  updated_at   : ISO
}
```
- 키: `(vessel_id, mid_cat)` 유일. 입력/엑셀 업로드는 upsert.

### 4.2 공용 헬퍼 (lookup 단일 소스)

```
getItemCategory(itemCode) → { model, mid_cat, name } | null
```
- 출처: `bom_catalog`. 매핑 키는 `item_code`.
- **충돌 규칙**: 같은 `item_code`가 모델별로 다른 중분류면 `model + item_code`로 해소. (재고 그룹은 중분류 단위 합산이므로 1차에선 `item_code` 단일 매핑을 기본으로 하고, 충돌 발견 시 모델 보조키 적용.)
- **미분류 처리**: BOM에 없는 `item_code`는 중분류 **"(미분류)"** 그룹으로 모아 표시(데이터 누락 가시화).

## 5. BOM 엑셀 파서 확장 (`js/phase0.js`)

- 현재 파서(`parseBOMSheet` 류)는 A=구분, B=모델, C=자재관리코드, D=품명, F=소요량, L~N=완제품코드 매핑만 읽는다.
- 재작성 BOM에 **중분류 컬럼**을 추가하고, 파서가 각 품목 행에서 중분류를 읽어 `items[].mid_cat`에 저장하도록 확장.
- 컬럼 위치는 재작성 BOM 확정 후 인덱스 1곳만 조정(파서가 인덱스 기반이라 변경 최소).
- `saveBOMItems()`에서 `vessel_bom.push(...)` 시 `mid_cat`도 함께 기록.

## 6. 재고 탭 — 중분류 2단계 (`js/phase5.js`, `index.html`)

### 6.1 Level 1 — 중분류 목록 (최상위)

```
[재고] 현황 — 중분류 기준
중분류            품목수   재고   임박 납품      판정
● Main Rack        5       38     2026-03-10    ● 충족
● Client Server    4       6      2026-04-05    ● 부족 2
● Camera Housing   6       12     2026-05-20    ● 여유
```
- `refreshInventoryGroups()`를 중분류 그룹 기준으로 재구성: 재고 품목을 `getItemCategory`로 중분류에 매핑해 집계.
- 각 행: 품목 종수, 재고 합계, 가장 임박한 납품예정일, 충족 신호등(6.3 계산).

### 6.2 Level 2 — 중분류 클릭 상세 (재고 + 계획 동반)

중분류 클릭 시 상세 카드에 **두 블록**을 함께 표시:

**(a) 하분류 품목 S/N 재고 상세** — *현재 재고현황 양식·버튼 그대로 재사용*
- 기존 `_renderInventoryDetail`의 컬럼/스타일/체크박스/출고·대여·검사요청 동작을 그대로 쓰되, 필터를 "해당 중분류에 속한 모든 item_code"로 변경.

**(b) 3개월 납품계획 · 추가발주 (MRP-lite)** — 6.3

### 6.3 3개월 납품계획 계산 (중분류 상세 (b) 블록)

선택 중분류 M에 대해, **전 호선 합산** 기준 시간순(time-phased) 표:

```
Main Rack — 3개월 납품계획 (전 호선 합산)
납품예정일    호선     필요   누적필요   가용(재고+입고예정)   잔여    판정
2026-03-10   3445     30     30         42                   12     ● 충족
2026-04-05   2925     18     48         42                   -6     ● 부족 6 «발주»
```
- **가용재고** = 해당 중분류 item_code들의 `IN_STOCK` 합계 (공용 풀)
- **입고예정** = 해당 item_code들의 미입고 PO 수량 = `po_line.ordered_qty − 입고스캔수량` (status OPEN/PARTIAL)
- **누적필요** = 납품예정일 오름차순으로 필요수량 누적
- **잔여** = (가용재고 + 입고예정) − 누적필요
- **판정**: 잔여 ≥ 0 → 충족 / 잔여 < 0 → 부족(추가발주 = |잔여|)
- 신호등 색: 충족=초록, 부족=빨강. (리드타임 도입 시 "납품예정일−리드타임 < 오늘 & 부족" → 진한 빨강 "지연")
- 표시 범위: 오늘 ~ +3개월의 `delivery_schedule` 행.

## 7. SCM 신규 "납품일정" 탭 (`js/phase-delivery.js` 신규)

좌측 사이드바 SCM 그룹에 서브탭 추가. 서브탭 2개: **입력 / 계획(6개월)**.

### 7.1 입력
- **직접 입력**: 호선 선택 → 그 호선 BOM의 중분류 목록 자동 나열 → 중분류별 납품예정일·실제납품일·비고 입력 → `delivery_schedule` upsert.
- **엑셀 파싱**: 고정 템플릿(호선명, 중분류, 납품예정일[, 실제납품일]) 다운로드 → 업로드 → **호선명 매칭 + (vessel_id, mid_cat) upsert** (미일치 행은 건너뜀). CX/OP 엑셀 매핑 패턴(`downloadCxopTemplate`/`onCxopExcelUpload`/`applyCxopExcel`) 재사용.

### 7.2 계획 (6개월 타임라인)
```
[SCM ▸ 납품일정 ▸ 계획]                3월   4월   5월   6월   7월   8월
3445 / Main Rack                       ✓
3445 / Client Server                         ●부족
3445 / Camera Housing                              ●
2925 / Main Rack                                   ●
```
- 행 = 호선×중분류, 열 = 향후 6개월(월 단위). 셀 = 납품예정(●)/실제납품(✓), 6.3 판정으로 부족 강조.
- 재고 탭이 3개월 운영 시야라면, 이 탭은 6개월 전략 시야 — 동일 데이터, horizon만 확대.

## 8. 중분류 그룹 표시 — 적용 범위

1차 필수: **재고 탭**(6장).

품목 목록이 나오는 다른 표도 동일 패턴(중분류 그룹 헤더) 적용 후보. 공용 유틸 `groupByMid(items, getCode)`(중분류 정렬 + 헤더 행 삽입)로 재사용:
- 안전재고(설계 탭) `tbl-safety-by-item`
- 발주 품목 내역 `tbl-line`
- 출고 탭 `tbl-outgoing-stock`
- 검사요청 `tbl-insp-*`

> **확인 필요**: 위 표들까지 1차에 포함할지, 재고 탭부터 적용하고 순차 확장할지. (기본 제안: 재고 탭 우선, 나머지는 2차)

## 12. 출고·납품 실행 설계 (2026-07-04 확정 · 구현)

### 12.1 확정된 결정
| 항목 | 결정 |
|------|------|
| 출고 방식 | **제품 QR 스캔이 주(主), 버튼은 예외/보조.** 순수 QR-only는 목적지·수량 검증 불가라 지양 |
| 컨텍스트 | 별도 "납품지시서" 문서 없음 → **`delivery_schedule`(호선×중분류 일정)가 디지털 납품지시서** 역할. 100%·누락체크의 기준(분모) |
| 단일 퍼널 | **모든 출고는 [납품·출고] 탭의 "출고 세션" 한 곳에서만.** 버튼 출고 = 세션 내 예외 모드. **재고현황 탭엔 출고 없음**(대여·검사요청·이력만). 기존 SCM 출고 서브탭은 신규 탭 검증 후 **은퇴 예정** |
| 재고=풀 | 재고는 호선 무관 공용 풀. **호선은 출고(스캔) 시점에만 배정** |
| 대여/검사 | 출고가 아닌 내부업무 → 재고현황 탭 버튼 유지 (출고=QR, 내부업무=버튼) |
| 문서 단일 소스 | Packing List·박스목록은 **1회 생성·저장 후** 호선별 출고현황·문서산출물에 **링크만**(복제 금지) |
| 박스 QR (Phase 2) | 박스=단일 호선. 박스 QR(호선·중분류·납품일자 태그) 스캔=세션 헤더 대체. **패킹=출고 단일 스캔**(적재 스캔과 출고 스캔을 분리하지 않음). 도착지 박스 QR 재스캔=2중 체크(옵션) |

### 12.5 중분류/하분류 전면 적용 계획 (BOM 재작성 후 일괄 활성화)
현재 BOM은 중분류로 안 나뉘어 있어 `getItemCategory()`가 `null` → 시스템이 **관대 모드**(미분류=전체 표시, 오배송 미차단)로 동작한다. **BOM 신규 입력 시 중분류·하분류를 완벽히 나누면**, 아래가 자동 활성화된다.

- **단일 소스 원칙**: 모든 화면은 품목의 분류를 **`getItemCategory(item_code)` 한 곳**에서만 조회한다(중복 저장·개별 매핑 금지). BOM만 바로잡으면 전 화면이 동시에 정확해진다.
- **유일한 선행조건**: BOM 파서(`js/phase0.js`)가 재작성 BOM의 **대분류·중분류·하분류 컬럼을 읽어 `vessel_bom`(및 `bom_catalog`) 품목에 저장**해야 한다. `getItemCategory`는 이 필드를 읽는다.
- **하분류 정의**: 대분류(=모델) → 중분류(조립체) → **하분류(개별 품목 = `item_code`/`item_name`)**. "중분류-하분류로 확인" = 품목(하분류)을 중분류로 묶어 확인. (만약 하분류가 품목 위 추가 카테고리 레벨이면 `getItemCategory` 반환을 `{major,mid,sub,item}` 4단계로 확장)

**중분류/하분류-aware로 전환할 화면 (BOM 재작성 후)**
| 화면 | 적용 |
|------|------|
| 재고현황(재고 TAB) | 중분류 최상위 그룹 → 하분류(품목) S/N (설계 §6) |
| 납품·출고 [출고 작업] | 예외 선택·스캔 검증을 해당 중분류 품목으로 자동 한정(현재 관대 모드 자동 해제) |
| 안전재고(설계 TAB) | 품목 목록을 중분류로 그룹 표시 |
| 발주 품목 내역 / 검사요청 | 중분류 그룹 헤더(공용 `groupByMid`) |
| 납품일정 입력 | 중분류 드롭다운을 BOM 중분류 목록으로 확정(현재는 자유입력+자동완성) |

→ 즉 지금은 **구조(단일 소스·파서 훅)만 깔아두고 관대 모드**, BOM 재작성 시 **파서 한 곳 + 각 화면 그룹핑 결선**으로 전면 활성화한다.
