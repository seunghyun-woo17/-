# 모듈별 코드 가이드 — 개요

> Avikus 부산사무소 ERP (구매·자재관리) — `Phase1_파일분리/js/` 코드맵
> 정리일: 2026-06-15 (중간 점검 / 타 개발자 핸드오프 목적)

이 폴더는 `Phase1_파일분리/js/`의 JS 파일을 "개발 로직(모듈) 단위"로 정리한 문서입니다.
**실제 코드 파일의 위치·이름은 변경되지 않았습니다.** 아래는 각 파일의 역할·핵심 함수·연관 관계를
정리한 인덱스이며, 코드를 직접 찾아갈 때 참고용으로 사용합니다.

## 2. 스크립트 로딩 순서 (index.html)

```
db.js → utils.js → qr.js
  → phase0.js → phase1.js → phase23.js → phase4.js → phase5.js → phase-inspection.js → phase-cxop.js → phase-fat.js
  → app.js   (반드시 마지막)
  → (DEV ONLY) dev-mock.js
  → jsQR (CDN, 카메라 QR 디코딩)
  → xlsx/SheetJS (CDN, BOM 엑셀 파싱)
```

뒤에 로드되는 파일은 앞에서 정의된 전역 함수/변수(`DB`, `notify`, `today`, `getVesselDisplayName` 등)에
의존합니다. 순서를 바꾸면 `ReferenceError`가 발생할 수 있습니다.

### 외부 CDN 의존성 (오프라인/서버 환경 전환 시 주의)
| 라이브러리 | 용도 | 사용처 | CDN 실패 시 |
|---|---|---|---|
| jsQR 1.4.0 | 카메라 프레임에서 QR 디코딩 | [phase23.js](06_phase23.md) `scanFrame()` | 카메라 스캔 불가, 수동 입력으로 대체 (콘솔 경고만 출력) |
| xlsx(SheetJS) 0.18.5 | BOM 엑셀(.xlsx) 파싱 | [phase0.js](04_phase0.md) `onBomExcelUpload()`/`parseBomExcel()` | BOM 엑셀 업로드 기능 사용 불가 (콘솔 경고만 출력) |

오프라인 사내망(DELL XE3) 배포 시에는 위 두 라이브러리를 로컬 파일로 다운로드해 `index.html`의 `<script src>`를 교체해야 합니다.

## 3. 핵심 데이터 흐름

```
[Phase 1] PO 발행
   └─ po_header / po_line 생성, PO QR 발급 (A-PO-YYNNNN)

[Phase 2·3] 입고 검수
   └─ PO QR 스캔 → 제품 QR 스캔(단건/일괄)
   └─ 입고 완료 → incoming_header / incoming_line 생성
                 → inventory(S/N) 생성 (status: IN_STOCK, vessel_assigned = po.vessel_code)
   └─ 서류 첨부 모달 → inspection_cert (검사성적서/COC/거래명세서, incoming_id 단위)

[재고 탭] inventory 품목별 그룹 → S/N 드릴다운
   └─ 출고/대여/검사요청 → outgoing_log 기록, inventory.status 변경 (SHIPPED/RENTED/INSPECTION_REQUESTED)

[SCM > 출고 처리] QR 스캔 또는 목록 선택 → openOutgoingModal(action, items)

[검사요청 탭] outgoing_log(action=INSPECTION_REQUESTED) → 팀별(QC/SW/공통) 집계 → 완료 처리
   └─ 완료 시 currentUserName(전역, utils.js)을 검사자로 자동 기록

[문서 산출물 탭] 호선별 문서 허브 (2026-06 개편)
   └─ inventory(status=SHIPPED, vessel_assigned) 기준 호선별 그룹화
   └─ incoming_line.mc_code === inventory.mc_code → incoming_header → inspection_cert (자동 집계)
   └─ vessel_docs (FAT/SW설치/기타 — 수기 첨부, vessel_id FK)
```

## 5. 핵심 설계 원칙 (요약 — 상세는 `../../CLAUDE.md` 참고)

- **db.js 단일 교체 전략**: localStorage 접근은 db.js에만 집중 → 서버 전환 시 이 파일만 `api.js`로 교체하면 나머지 phase*.js는 수정 불필요
- **성적서 1장 → N개 S/N 자동 연결**: `inspection_cert`는 `incoming_id` 단위로 1회만 첨부, 해당 입고건의 모든 S/N에 `cert_id`가 일괄 연결됨
- **PO 번호 형식**: `A-PO-YYNNNN` (연도 2자리 + 4자리 순번, 매년 0001부터 재시작 — 서버 전환 후 동시성 보장 위해 서버 채번 필요)
- **QR은 데이터 컨테이너가 아닌 조회 키**: 제품 QR의 `MC`(mc_code) 값으로 `DB.inventory`를 조회 — QR 자체에 전체 데이터를 담지 않음
- **refreshAllViews()**: DB를 변경한 뒤에는 항상 `db.js > refreshAllViews()`를 호출(또는 그 안에 포함된 개별 refresh 함수)하여 화면을 갱신. 새 뷰를 추가했다면 이 함수에도 등록 필요
