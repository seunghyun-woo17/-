# DB 전환 3단계 로드맵

---

## Phase 1 — 파일 분리 (기능 변화 없음)

**목표:** localStorage는 그대로, 코드만 정리  
**검증:** 분리 후 탭/버튼/저장 모두 동일하게 작동하면 성공

```
avikus_v2.html (1953줄)
  ↓ 분리
css/ + js/ 11개 파일 (기능 동일, localStorage 유지)
```

### 이 단계의 핵심 설계 포인트

`js/db.js` 를 설계할 때  
localStorage를 직접 건드리는 코드를 이 파일 하나에만 몰아넣는다

→ 나중에 DB 전환 시 db.js 하나만 api.js로 교체하면 끝  
→ phase0.js, phase1.js 등은 수정 불필요

### db.js 설계 예시 (미래를 고려한 인터페이스)

```javascript
// 지금은 localStorage, 나중에는 이 파일만 바꾸면 됨
const DB = {
  getAll: (table) => JSON.parse(localStorage.getItem(table) || '[]'),
  save:   (table, data) => localStorage.setItem(table, JSON.stringify(data)),
  reset:  () => { /* ... */ }
}
```

## Phase 2 — 서버 + DB 환경 구축 (코드 건드리지 않음)

**목표:** DELL XE3에 Node.js + PostgreSQL 설치 및 테이블 생성  
프론트엔드 코드는 아직 변경 없음

**작업 내용:**
1. DELL XE3에 Node.js 설치
2. PostgreSQL 설치 + DB 생성
3. 테이블 schema.sql 작성 및 실행
4. API 서버(backend/) 작성
5. Postman 등으로 API 단독 테스트

---

## Phase 3 — 프론트엔드 DB 전환

**목표:** `js/db.js` (localStorage) → `js/api.js` (서버 통신) 교체  
phase0~5.js는 호출 방식만 변경, 로직은 그대로

```
변경 전: DB.getAll('po')          ← localStorage 읽기
변경 후: await API.get('/api/po') ← 서버에서 가져오기
```
